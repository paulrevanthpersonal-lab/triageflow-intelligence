    VERSION 1.0.0
    TF-IDF + LOGISTIC REGRESSION

    Interpretable by design.

    TriageFlow uses separate multiclass pipelines for service category and operational priority. Linear feature weights make influential ticket terms inspectable, while probability thresholds route ambiguous decisions to people.

    INTENDED USE

    Decision support—not decision replacement

    • Initial triage for internal IT service requests
    • Assignment-group and SLA recommendations
    • Learning and portfolio demonstration with synthetic text

    OUT OF SCOPE

    • Autonomous ticket closure or user-impact decisions
    • Employee performance or disciplinary evaluation
    • Emergency, medical, or life-safety dispatch

    KNOWN LIMITATIONS

    What reviewers should challenge

    1. 01
      Synthetic language

      Real ticket vocabulary, spelling, languages, and organizational context will differ.

    2. 02
      Probability calibration

      Confidence supports review routing but is not a guarantee of correctness.

    3. 03
      Operational context

      Impact, asset criticality, and service dependencies require trusted system integrations.

    SYSTEM DESIGN

    A small system with
    production-shaped thinking.

    TriageFlow reconstructs my B.Tech intelligent help-desk classification project as a modern, reviewable portfolio implementation. It demonstrates the full lifecycle: data generation, model training, API delivery, operator experience, feedback, observability, testing, and documentation.

    01 / EXPERIENCE

    Accessible operator workspace

    Semantic HTML, responsive CSS, keyboard navigation, and explicit confidence states.

    →
    02 / SERVICE

    Typed FastAPI boundary

    Validated intake, batch classification, queue, feedback, metrics, and model-card endpoints.

    →
    03 / INTELLIGENCE

    Two explainable pipelines

    TF-IDF features and logistic regression for category and priority predictions.

    →
    04 / EVIDENCE

    SQLite decision trail

    Saved classifications, review flags, and operator feedback for future evaluation.

    01

    Confidence is visible

    Operators see alternatives, thresholds, and influential terms—not a black-box label.

    02

    Humans own outcomes

    Critical or uncertain tickets require validation before operational action.

    03

    Evidence is reproducible

    Seeded data, deterministic training, tests, model metrics, and CI support review.
